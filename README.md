# resume2JD｜不再写简历

[English](README.en.md)

**给一个岗位 JD，自动输出一份匹配的定制简历。**

resume2JD 是一个面向求职场景的 AI Skill。你只需把个人经历整理成一份“个人详历”（没错，是“简历”的反义词），以后把招聘 JD 的截图或文字发给 Agent，就能生成针对该岗位的定制简历（HTML/PDF）、匹配分析、公司与岗位发展前景及履历长期增值分析、多角色面试模拟与定向反问，减少重复改简历的工作，且所有个人经历都来自真实详历，不编造。

## 你会得到什么

- **定制简历**：Markdown + 单文件 HTML；PDF 可直接通过浏览器保存，环境已支持时也可用 PDFKit 自动生成。
- **匹配分析**：列出岗位关键要求、对应经历、优势与缺口，并给出简历筛选邀约区间。
- **发展与履历增值分析**：以未来 2–3 年为观察期，评估公司基础、岗位成长、能力复利、证据增值和机会成本；区分事实、推断与待验证假设。
- **面试模拟与反问**：推断 1–3 类面试官，提供 8–12 个分角色问题、压力追问、约 60 秒自我介绍、面试风险雷达和按角色设计的反问；回答均保留真实经历来源。
- **事实追溯**：关键内容标注详历来源编号，不编造技能、职责、数字或成果。

> “邀约区间”只是基于简历与 JD 文本的未校准判断，不是真实统计通过率，也不代表录用承诺。发展前景与履历增值分析同样不是结果预测；信息不足时会明确标注并降低置信度。

## 为什么“不再写简历”

AI 浪潮下，岗位边界正在变化，岗位定义越来越模糊，新岗位和复合岗位会越来越多。简历不应只是堆砌 JD 关键词，而应回答两件事：**这个岗位要解决什么问题，你的哪些真实经历能证明你可以解决它。** 一份详历持续沉淀经历，每次投递只重新选择和组织证据。

## 使用前准备

- 一个能读取、写入本地文件的 AI Agent；使用 JD 截图时还需支持图片理解。
- 一个现代浏览器。Windows 可用系统自带的 Microsoft Edge，macOS 可用 Safari，也可用 Firefox；**不要求安装 Chrome**。
- 普通使用无需安装 Node.js、Python、PDFKit，也无需配置 API Key。所选 AI 工具自身可能有账号或模型要求。

这不是独立软件或在线网站，需要 Agent 读取并执行 `SKILL.md`。

## 新用户快速开始

### 1. 获取并打开项目

- 不熟悉 Git：在 GitHub 页面选择 **Code → Download ZIP**，解压后用 Agent 打开 `resume2JD` 文件夹。
- 熟悉 Git：执行以下命令：

```bash
git clone https://github.com/Gzz9527/resume2JD.git
```

支持 Skill 安装的 Agent 也可按其产品文档注册本目录；支持工作区的 Agent 直接打开文件夹即可。

### 2. 让 Agent 帮你建立个人详历

不必先手填完整模板。根据现有材料选择一种方式，原始文件不会被修改：

**已有旧简历、经历清单或文本文档**

把文件放入 `inputs/`，然后发送：

```text
读取当前工作区的 SKILL.md。
我还没有个人详历，请根据 inputs/ 里的材料帮我初始化。
先创建草稿并列出缺失或冲突信息，不要修改原始材料，也不要编造。
```

没有本地文件时，也可以直接把旧简历或经历文字发给 Agent。

**没有整理过的材料**

```text
读取当前工作区的 SKILL.md。
请通过分步提问帮我创建个人详历，先从基本信息、最近一段工作和一个代表项目开始。
```

**希望自己填写**

复制 `templates/个人详历快速模板.md` 为根目录 `个人详历.md`。先填基本信息、工作经历、代表项目和教育背景即可；`templates/个人详历模板.md` 是后续补全证据时使用的完整模板。

初始化阶段，Agent 默认创建 `个人详历.draft.md`，不会覆盖已有详历。检查草稿后发送“确认这份草稿作为我的个人详历”，Agent 才会在根目录不存在同名文件时将其转为 `个人详历.md`。后续生成简历时，详历恢复只读。

### 3. 发送 JD，生成岗位版本

直接发送 JD 截图或粘贴招聘文字，并说：

```text
基于个人详历.md 和这份 JD 生成定制简历。
```

Agent 会按 JD 选择真实经历，而不是把所有经历重新排版一遍。每次生成使用新目录，不覆盖历史版本。

## PDF：无需额外环境的通用方案

1. 打开生成的 HTML，点击页面中的 **“打印 / 保存 PDF”**；也可使用浏览器打印功能。
2. 选择“另存为 PDF”或“保存为 PDF”。
3. 设置 **A4、纵向、100%/默认缩放、默认边距**，关闭浏览器页眉页脚。

Windows 没有 Chrome 时直接用 Edge；macOS 可直接用 Safari。该路径生成的是浏览器打印 PDF，不应被宣称为 PDFKit 输出。

**PDFKit 是可选增强，不是使用门槛。** 仅当当前环境已经具备 PDFKit 生成与检查能力时，Agent 才自动输出并验收同名 PDF；不得为了完成普通投递要求用户安装编程环境。无法自动生成时，应明确说明并提供上述 HTML 路径。

## 先跑虚构示例

`examples/demo/` 中的人物、公司、数字、联系方式和岗位均为虚构。发送：

```text
读取 SKILL.md，用 examples/demo/career-master.md 和
examples/demo/job-description.md 运行完整流程，输出到 outputs/demo-run/。
```

可将结果与 `examples/demo/expected/` 对比。不同模型的措辞可不同，重点检查事实保真、来源映射、发展评估的事实/假设区分、文件完整性和 HTML 打印效果。

## 默认输出

每次在 `outputs/<版本>/` 中生成：

- `JD原文.md`：JD 文字副本；截图识别不清处标记待确认。
- `<姓名>-<目标岗位>-<目标公司>.md`：便于修改和 ATS 文本复用。
- `<姓名>-<目标岗位>-<目标公司>.html`：可浏览、可打印的单文件简历。
- `<姓名>-<目标岗位>-<目标公司>.pdf`：环境支持时自动生成，或由用户通过 HTML 保存。
- `岗位匹配与邀约评估.md`：匹配分析、来源映射、邀约区间，以及公司与岗位发展前景和履历长期增值分析。
- `面试模拟与反问.md`：面试官角色推断、8–12 个分角色问题、压力追问、开场准备、风险雷达和定向反问。
- `校验与待确认.md`：仅在存在失败、建议或存疑项时生成。

## 隐私与安全边界

- 根目录详历、草稿、`inputs/`、`outputs/` 已加入 `.gitignore`，但提交前仍必须检查 `git status`。
- 不要在公开示例、Issue、PR、截图或 CI 日志中放入真实联系方式、详历、JD、雇主保密信息或密钥。
- 云端 AI 可能把个人资料发送给外部服务商；使用前确认其数据政策，或选择合适的大模型部署方式。
- “详历只读”是 Agent 工作流约束，不是文件系统权限；重要资料请另行备份。
- HTML 不请求外部字体或脚本，可离线打开；最终投递前必须人工核对事实、分页和联系方式。
